2. Dashboard
Purpose
The dashboard provides a quick overview of the competition's current status.
Visible statistics
Statistic	Description
Total Teams	Total registered/created teams
Active Teams	Teams currently active
Pending	Teams awaiting activation/approval, if applicable

Dashboard functionality

3. Team Management
Team management has two subsections:
1. Register Team
2. All Teams
3.1 Register Team — Create Team
This is an admin-only operation. Participants cannot create their own teams through the admin functionality.
Team registration fields
Field	Type	Requirement
Team Name	Text	Required, unique
Number of Members	Number	Configurable
Robot Theme / Category	Dropdown	Select from available competition categories
Member 1 Name	Text	Required
Member 1 Email	Email	Required
Member 2 Name	Text	Required
Member 2 Email	Email	Required
Additional Members	Dynamic fields	Based on member count

The member fields dynamically increase/decrease according to the selected number of members.
Team creation flow
1. Admin opens Register Team.
2. Admin enters the team name.
3. Admin selects the number of members.
4. Admin selects the team's robot category/theme.
5. Member information fields are dynamically generated.
6. Admin enters member names and emails.
7. Admin submits the registration.
8. The system creates the team record.
9. The system creates team login credentials.
10. The admin receives/displays the generated credentials.
11. The credentials are handed to the team manually.
Credentials
The reference shows an intended credential format similar to:
- Username: teamname
- Email/login identifier: team-based identifier
- Password: generated password
Recommended implementation: generate a unique username and a temporary random password. Passwords should never be stored in plaintext. Supabase Auth should handle authentication.

The admin should ideally have a Copy Credentials button and a one-time password display.
Important team restrictions
- Only admins can create teams.
- Team names should be unique.
- Login credentials should be unique.
- A team should have one account.
- Team information should be editable by admins.
- Admins should be able to deactivate a team.
- Admins should be able to reset team passwords.
- Deleting a team should require confirmation.
- Team members should not be able to create additional accounts or teams.

5. Leaderboard Management
This section allows the admin to manually assign, update and remove scores for teams.
Interface
- Stage selector
- Add/Update Score form
- Team search
- Score input
- Update Score button
- Stage-specific leaderboard table
Score update form
Field	Description
Stage	Selected competition stage
Team	Search/select team
Score	Numeric score

Leaderboard table
Column	Description
Rank	Automatically calculated
Team	Team name
Score	Current score for selected stage
Actions	Remove entry

Functionality
- Select a stage.
- Search teams.
- Add a score.
- Update an existing score.
- Remove a score entry.
- Automatically rank teams.
- Display highest scores first.
- Recalculate rankings after score changes.
- Support ties.
- Maintain separate score records per stage.
Important design recommendation
Scores should not simply be stored as manually assigned ranks.

The backend should store actual numeric scores, and ranking should be calculated automatically:

Rank = ordered position based on score

This ensures rankings remain consistent when scores change.

2. Settings
3. Results
This is one of the most important sections because the reference includes a complete question bank and stage-wise quiz control system.

The admin should be able to create questions independently and later select which questions belong to a particular stage's quiz.

Question bank functionality

- Edit existing questions.
- Delete questions.
- Search questions.

- View all available questions.
- Store questions independently from quizzes.
Quiz assembly
Admin should be able to:
1. Select a stage.
2. Open the question bank.
3. Browse available questions.
4. Select questions to include.
5. Add selected questions to that stage's quiz.
6. Remove questions from the stage quiz.
7. Rearrange question order.
8. Save the quiz configuration.
Critical distinction: Creating a question does not automatically add it to a quiz. Questions must be selected and assigned to the relevant stage.

12. Admin Panel Permissions
The admin panel should have a strict permission boundary.
Admin can:
- Create teams.
- Edit teams.
- Reset team credentials.
- Disable teams.
- Create schedule entries.
- Manage stages.
- Create and manage quizzes.
- Assign quiz questions.
- View quiz results.
- Manage leaderboard scores.
- Upload content.
- Manage live sessions.
- Create notifications.
- Configure competition status.
Team participants cannot:
- Access admin routes.
- Create teams.
- Create admin accounts.
- Modify other teams.
- Change quiz questions.
- Modify scores.
- Change competition schedules.
- Publish content.
- Modify notifications.
- Access administrative database functions.
Admin authorization must be enforced on the backend, not merely by hiding buttons in the frontend.

Record actions such as:

- Team edited
- Team disabled
- Password reset
- Quiz activated
- Quiz deactivated
- Quiz schedule changed
- Questions added
- Questions removed
- Scores updated
- Material uploaded
- Notification created
- Notification disabled
- Stage content published
Each activity should ideally record:
- Admin identifier
- Action
- Target entity
- Timestamp
- Previous value
- New value
This helps recover mistakes and maintain accountability during the event.
