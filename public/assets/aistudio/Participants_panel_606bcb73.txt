# SPECTEQ 2027 — STUDENT PORTAL / PARTICIPANT DASHBOARD

## OBJECTIVE

Develop a complete, functional, authenticated Student Portal for SpecteQ 2027 participants.

The Student Portal is the interface through which registered teams manage their participation, access learning resources, complete competition stages, take quizzes, submit assignments, monitor progress, view schedules, receive announcements, and communicate with organizers.

This is a separate section from:

1. The public SpecteQ website.
2. The Admin Panel.
3. The main website leaderboard.

The Student Portal should use a clean, professional, modern dashboard design inspired by the provided screenshots.

---

# 1. STUDENT PORTAL LAYOUT

Create a responsive dashboard layout consisting of:

### Sidebar Navigation

- Dashboard
- Team Members
- Task Materials
- Active Stages / Tasks
- Competition Schedule
- Announcements
- Team Profile / Settings
- Contact Support
- Logout

The sidebar should be collapsible on desktop and become a drawer on mobile.

The sidebar should dynamically display active stages/tasks based on the configuration and activation status set by the administrator.

### Top Navigation Bar

Include:

- Current page title
- Team name
- Notification bell
- Unread notification count
- User profile menu
- Profile settings
- Logout option

Use a consistent navigation structure across all student pages.

# 5. DYNAMIC STAGE AND TASK SYSTEM

THIS IS A CORE FUNCTIONALITY OF THE STUDENT PORTAL.

The administrator should be able to create, configure, publish, activate, deactivate, and manage stages/tasks through the Admin Panel.

When the administrator activates a stage/task, it should automatically become accessible to the appropriate participants through their Student Portal.

Do not manually hardcode individual stage pages.

Instead, create a reusable dynamic Stage/Task Page template.

Each stage/task should be populated using the information configured in the Admin Panel.

## Stage Configuration Should Support

- Stage number
- Stage title
- Task title
- Description
- Start date
- Deadline
- Guidelines
- Learning materials
- Quiz
- Assignments
- Submission requirements
- Evaluation criteria
- Completion requirements
- Visibility
- Activation status
- Unlock conditions
- Attempt limits
- Passing criteria

The system should support any number of stages.

## Sidebar Behavior

When a stage is activated:

- It becomes accessible to eligible students.
- It appears in the Student Portal navigation.
- Students can open the corresponding stage page.
- The stage status is displayed.

When a stage is inactive or unpublished:

- It should remain inaccessible.
- It may be displayed as locked/upcoming if configured by the administrator.

The student portal must dynamically update when the administrator changes the stage status.

- Rules

- Safety instructions

- Evaluation criteria

- Headings
- Paragraphs
- Bullet lists
- Numbered lists
- Images
- Links
- Embedded videos
- Documents
- Downloadable files

- Description

- Time limit, if applicable
- Number of attempts allowed
- Quiz instructions
- Start Quiz button

### Supported Question Types

- Single-choice questions
- Multiple-choice / multiple-select questions
- True or False
- Short-answer questions
- Numerical questions
- Image-based questions

### Quiz Interface

The quiz interface should support:

- Question navigation
- Previous / Next buttons
- Question progress
- Answer selection
- Automatic saving of answers
- Mark for review

- Timer, if applicable

- Submission confirmation

- Attempt limit
- Time limit

- Answer option randomization
- Auto-evaluation
- Manual evaluation
- Reveal correct answers
- Show score immediately
- Best score or latest score policy

Students should be able to view their attempt history when permitted.

## F. STAGE COMPLETION

Stage completion requirements should be configurable.

Possible requirements:

- Guidelines reviewed
- Required materials completed
- Quiz passed
- Assignment submitted
- Assignment approved

When requirements are satisfied:

- Mark the stage completed.
- Update the student's overall progress.
- Update dashboard progress cards.
- Unlock the next stage when appropriate.

Do not assume every stage must contain a quiz or assignment.

Stages should support flexible configurations.

# 13. LEADERBOARD

The leaderboard is planned to be hosted on the MAIN PUBLIC SPECTEQ WEBSITE.

Therefore:

- Do NOT create a dedicated leaderboard page inside the Student Portal navigation.
- Do NOT duplicate the public leaderboard inside the student dashboard.
- Do NOT make the student portal responsible for displaying the main leaderboard.

The Student Portal may display individual/team performance statistics and stage scores privately, but the public competition leaderboard will be handled separately by the main website.

- Dynamic task loading
- Dynamic materials loading
- Quiz functionality
- Quiz submissions
- Assignment submissions
- Progress tracking

---

# 16. DATA AND PERMISSIONS

Students should only be able to access:

- Their own account
- Their registered team
- Their team's submissions
- Their team's progress
- Authorized stage/task content
- Published announcements
- Publicly accessible schedule information

Students must not be able to:

- Access the Admin Panel
- Modify administrator-controlled stage content
- Modify quiz questions
- View other teams' private submissions
- View private evaluation data belonging to other teams
- Modify scores
- Access unpublished materials
- Bypass stage restrictions

Implement secure backend permissions rather than relying only on frontend visibility.

# FINAL REQUIREMENT

The Student Portal must feel like a complete participant platform where teams can manage their entire SpecteQ journey from registration to final competition.

It should not be a collection of disconnected static pages.

Every page must be connected through a consistent navigation system, and all stages, tasks, materials, quizzes, deadlines, announcements, and progress should be dynamically managed by the Admin Panel.

Use the provided screenshots as UI references, but improve the overall design, functionality, responsiveness, and user experience.

Keep the public leaderboard on the main SpecteQ website and do not include it in the Student Portal navigation.
